# Organização do trabalho

## Reunião inicial

Em **13 de setembro de 2026**, o grupo realizou uma reunião on-line utilizando o **Microsoft Teams**.

Durante a reunião foram discutidos:

- o problema apresentado na atividade;
- a proposta geral do ClinAgenda;
- as áreas profissionais necessárias;
- a divisão das responsabilidades;
- a organização do repositório;
- a forma de colaboração entre os integrantes.

## Definição dos papéis

Cada participante escolheu seu papel com base em sua afinidade com a área/stack.

A equipe ficou organizada da seguinte forma:

| Integrante | Papel |
|---|---|
| Carlos Alberto | Back-end |
| Hélio Vieira | UI/UX |
| Vitor Araújo | Banco de Dados |
| Ciro Junior | Front-end |
| Leonardo Pereira | Product Owner |

## Estratégia de branches

Cada integrante possuirá uma branch própria para produzir sua contribuição.

Branches planejadas:

```text
carlos-backend
helio-ui-ux
vitor-banco-dados
ciro-frontend
leonardo-product-owner
```

A branch `main` será utilizada para manter a versão consolidada do projeto.

## Fluxo de contribuição

O fluxo planejado é:

```text
main
  ↓
criação/atualização da branch individual
  ↓
produção da contribuição
  ↓
commit
  ↓
push
  ↓
Pull Request
  ↓
revisão
  ↓
merge na main
```

## Registro das decisões

As principais decisões serão registradas no próprio repositório por meio de:

- documentação em Markdown;
- histórico de commits;
- Pull Requests;
- alterações consolidadas na branch `main`.

Esse processo permite identificar como o projeto foi organizado e como as contribuições foram incorporadas.

## Responsabilidade coletiva

Embora cada integrante tenha uma área principal, a proposta final é responsabilidade do grupo.

As decisões que afetem o produto como um todo deverão ser discutidas entre os integrantes antes de serem incorporadas definitivamente à documentação.

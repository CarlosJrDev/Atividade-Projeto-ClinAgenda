## Critério de escolha

Os papéis profissionais foram definidos durante uma reunião on-line do grupo.

Cada integrante escolheu sua área considerando sua afinidade com a respectiva área/stack e a necessidade dessa função dentro do projeto.

A divisão não foi feita de maneira aleatória. Cada área possui relação direta com componentes necessários para a construção do ClinAgenda.

## Relação geral entre as áreas

### Product Owner

Ajuda a organizar as necessidades do produto, definir prioridades e manter o projeto alinhado ao problema das clínicas.

### UI/UX

Planeja como pacientes, médicos, recepcionistas e gestores interagirão com a solução, buscando uma experiência simples, compreensível e acessível.

### Front-end

Transforma os fluxos e interfaces planejados em telas e interações que os usuários utilizarão.

### Back-end

Implementa as regras de negócio, processamento dos agendamentos, controle de conflitos, autenticação e comunicação entre os diferentes componentes da solução.

### Banco de Dados

Estrutura e organiza os dados necessários para pacientes, médicos, unidades, agendas e atendimentos, contribuindo para integridade e disponibilidade das informações.

## Colaboração

As áreas precisam trabalhar de maneira integrada.

Exemplo de fluxo:


Product Owner
      ↓
Requisitos e prioridades
      ↓
UI/UX
      ↓
Front-end ↔ Back-end ↔ Banco de Dados


Essa representação não significa que o trabalho ocorra de forma isolada ou estritamente sequencial.

O Product Owner precisa conversar com todas as áreas, assim como UI/UX, Front-end, Back-end e Banco de Dados precisam alinhar decisões entre si durante o projeto.
